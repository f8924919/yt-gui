# オリジナル形式パネル

[← 目次](../index.md)

> 関連実装: [yt_gui/original_format_panel.py](../../arch/original_format_panel.md)

## 概要

`OriginalFormatPanel(QGroupBox)` が実装するパネルです。[オリジナル形式ダイアログ](original-format-dialog.md)（`OriginalFormatDialog`）に内包され、メインウィンドウの形式コンボで「オリジナルの形式」を選択したときに「詳細設定...」ボタンから開くダイアログ内に表示されます。

本ドキュメントはパネル内部のウィジェット構成・選択ロジック・フォーマット文字列生成を規定します。起動・追加/編集フロー・破棄などの画面挙動は [オリジナル形式ダイアログ](original-format-dialog.md) を参照してください。

動画の実際の映像・音声・字幕トラック一覧を yt-dlp で取得し、個別に選択してダウンロードできます。

---

## レイアウト構成

```
┌── オリジナル形式の詳細設定 ────────────────────────────────┐
│ 映像: [▼ 自動 (最良を選択)]              [形式を取得]    │
│ 音声:                     字幕:                          │
│ ┌──────────────────────┐ ┌────────────────────────────┐  │
│ │ 自動 (最良を選択)    │ │ ja - 日本語 [srt, vtt]     │  │
│ │ ダウンロードしない   │ │ en - English [srt, vtt]    │  │
│ │ opus (webm) [251] ja │ │ ja(自動生成) [vtt]         │  │
│ │ aac  (m4a)  [140] en │ │                            │  │
│ └──────────────────────┘ └────────────────────────────┘  │
│                          [▼ best] [MP4に埋め込む]        │
│ 出力: ● MP4 に結合  ○ remux のみ  ○ H.264 MP4 に再変換  ○ 音声のみ │
│ □ サムネイルを埋め込む  ☑ メタデータ  ☑ チャプター      │
└──────────────────────────────────────────────────────────┘
```

音声と字幕は左右 2 カラムで配置し、埋め込みオプション 3 つは 1 行に並べて縦圧迫を抑えています。

## 形式取得フロー

1. URL 入力欄に URL を入力
2. 「形式を取得」ボタンをクリック（またはキューアイテムの編集モード開始時に自動実行）
3. バックグラウンドスレッドで `Downloader.fetch_formats()` を呼び出す
4. 取得中は「取得中...」と表示してボタン・コンボを無効化
5. 取得完了後、映像・音声・字幕コンボ/リストに結果を反映

### エラー時

| 原因 | 表示 |
|---|---|
| プレイリスト URL を入力した | 警告ダイアログ（単独 URL を指定するよう案内） |
| その他エラー | エラーダイアログ |

## 映像コンボ

取得後の選択肢の構成:

```
自動 (最良を選択)
ダウンロードしない
1080p h264 (mp4) [137] – 3000kbps
720p h264 (mp4) [22] – 2000kbps ★
720p vp9 (webm) [247] – 1500kbps
...
```

`★` 印は映像・音声が合わさった複合フォーマットを示します。

### 複合フォーマット選択時の動作

★印の映像フォーマットを選択すると、音声コンボが自動的に `映像に含まれます` と表示されて無効化されます。

## 音声リスト

multi-select 対応の `QListWidget` (4 行表示、`ExtendedSelection`)。Ctrl+クリックで個別追加、Shift+クリックで範囲選択、修飾キーなしの再クリックで選択解除。

取得後の選択肢の構成:

```
自動 (最良を選択)
ダウンロードしない
opus (webm) [251] – 129kbps [ja]
aac (m4a) [140] – 128kbps
...
```

言語コードが含まれる場合は `[ja]` などのタグが付きます。

### 排他ロジック

| 操作 | 動作 |
|---|---|
| 「自動」を選択 | 「ダウンロードしない」と各音声 ID の選択を解除 |
| 「ダウンロードしない」を選択 | 「自動」と各音声 ID の選択を解除 |
| 音声 ID を選択 | 「自動」「ダウンロードしない」の選択を解除 |
| 複合フォーマット (★) の映像選択時 | リスト全体を 1 行 (`映像に含まれます`) 表示で `setEnabled(False)` に切り替える |

### 複数音声 → MKV 自動昇格

音声 ID を 2 件以上選択した状態でキューに追加する際、出力モードが「結合」(remux のみ・音声のみ以外) のとき、その**キューアイテムの動画コンテナを `mkv` に強制昇格**します（設定の動画コンテナ値そのものは変更しません）。昇格時はステータスバーに `status_multi_audio_mkv_promoted` を表示します。

「音声のみ」モードでは複数音声選択を許容しますが、**先頭の 1 トラックのみ使用**され、それ以外は無視されます（フェーズ 1 制約）。キュー追加時に `status_multi_audio_audio_only_truncated` を表示して注意喚起します。

## 字幕リスト

複数選択可能なリストウィジェット（4 行表示）。Ctrl+クリックで個別選択、Shift+クリックで範囲選択。修飾キーなしの左クリックで選択済みの行を再クリックすると、その行のみ選択解除されます。

取得後の表示:

```
ja – 日本語 [srt, vtt]
en – English [srt, vtt]
ja – 日本語 (自動生成) [vtt]
live_chat – ライブチャット (埋め込み不可・サイドカー保存) [json]      # YouTube Live のみ
comments – ニコニコ動画コメント (埋め込み不可・サイドカー保存) [json]  # ニコニコ動画のみ
danmaku – ビリビリ弾幕 (埋め込み不可・サイドカー保存) [xml]            # ビリビリ動画のみ
```

字幕が選択された場合のみ、字幕フォーマットコンボ（srt / vtt / best）と埋め込みチェックボックスが有効化されます。`live_chat` / `comments` / `danmaku` はコンテナへの埋め込み対象外で、選択しても常にサイドカー（json / xml）として保存されます（詳細: [ダウンロード動作 § サイドカー専用字幕の扱い](../features/download-behavior.md)）。

### 自動生成字幕の絞り込み

自動生成字幕（`automatic_captions`）は件数が多くなりがちなため、表示を次のルールで絞り込みます（手動字幕は絞り込みません）。

- `info["language"]`（動画の主言語）が判明している場合、**主言語と同じ言語ファミリー**（言語コードの `-` より前が一致。例: 主言語 `en` なら `en` / `en-US`）の自動字幕のみ表示します。ただし**手動字幕に存在する lang は主言語と異なっても残します**。
- 主言語が不明な場合は自動字幕を全件表示します。
- `live_chat` / `comments` / `danmaku` はサイドカー専用のため自動字幕としては表示せず（手動扱いの 1 行のみ）、重複しません。

実装は [`Downloader.fetch_formats`](../../arch/downloader.md) を参照。

## コメント・弾幕グループ

字幕リストの取得結果に `comments` lang（ニコニコ動画）または `danmaku` lang（ビリビリ動画）が含まれる場合に表示される `QGroupBox`。コメント/弾幕（ニコニコは JSON、ビリビリは Bilibili XML）→ ASS 変換に加え、ASS を**動画へ統合する 2 つの方式**（ソフトサブ MKV 統合 / ハードサブ焼きこみ）を提供する。両者は併設で、同時 ON も可能（それぞれ別ファイルを生成する）。ニコニコ・ビリビリのどちらの字幕が出現しても同一の UI・オプションを提示する。

構成は「チェック行（ASS 変換 / MKV 統合 / ハードサブ焼きこみ）＋ 解像度自動追従チェック ＋ パラメータグリッド（2 列 × 2 行）」。詳細設定が別画面化して高さに余裕が出たため、パラメータを横一列に並べず 2 列グリッドに折り返して横幅を抑える（解像度 [幅 × 高さ] / 表示時間 / 不透明度 / 文字サイズ倍率）。グループの可視化切替時には `updateGeometry()` でパネルの sizeHint を更新する。パネルを内包する [オリジナル形式ダイアログ](original-format-dialog.md) はレイアウトに追従してサイズが調整される（旧インライン埋め込み時の `QSplitter` 高さ再計算機構は不要になった）。

| ウィジェット | 既定値 | 説明 |
|---|---|---|
| コメントを ASS 字幕に変換 | OFF | ON 時に下記スピンボックスが有効化される。同時に字幕リストのコメント/弾幕行（`comments` または `danmaku`）も自動選択する |
| コメントを MKV に統合（ソフトサブ） | OFF | ON 時に「コメントを ASS 字幕に変換」を強制 ON にする。`{動画名}.with-comments.mkv` を別ファイルとして生成する（`-c copy`・無劣化・コメント表示の ON/OFF 可）。「音声のみ」「remux のみ」選択時は disable |
| コメントを焼きこむ（ハードサブ） | OFF | ON 時に「コメントを ASS 字幕に変換」を強制 ON にする。映像に ASS を焼き付けた `{動画名}.hardsub.mp4` を別ファイルとして生成する。**映像を H.264 / 音声を AAC に再エンコード**するため処理時間が増え画質が劣化する旨をツールチップで明示。「音声のみ」「remux のみ」選択時は disable |
| 動画の解像度を自動使用 | ON | ON のとき、実際にダウンロードした形式の width × height を ASS 解像度として採用する（映像「自動」選択時も同じ）。解像度を取得できないときは下記の手動値にフォールバック |
| 画面解像度 (幅 × 高さ) | 1280 × 720 | 出力 ASS の描画キャンバスサイズ。「動画の解像度を自動使用」が OFF のときの手動値 |
| 表示時間 (秒) | 8.0 | 流れる弾幕 1 件あたりの表示秒数。ビリビリだけに効く。ニコニコのときは無効になり、ツールチップで Web と同じ計算になることを示す（例外: ニコニコの変換に失敗して `danmaku2ass` に切り替えたときは、無効になったスピンボックスの値がそのまま使われる） |
| 不透明度 | 0.8 | 0.1〜1.0 |
| 文字サイズ倍率 | 100% | 25〜300%（ボタンの刻みは 5%）。100% が Web 表示相当の基準サイズ（基準と測定条件は表の下を参照）。解像度が変わっても動画に対する文字の比率はほぼ変わらない（整数への丸めによる小さな差はある。手動値（自動使用 OFF、または解像度を取得できないとき）が実動画と縦横比が異なる場合を除く）。ビリビリの位置指定弾幕には効かない |

ビリビリの弾幕の文字サイズは、基準の高さに基準比率と倍率をかけて決める。基準比率は 0.045。ニコニコのコメントは下の「ニコニコのコメントの変換」のとおりフォントの寸法から換算し、基準比率 0.09 はフォントが見つからないときと、`danmaku2ass` に切り替えたときだけ使う。基準の高さは ASS の解像度の高さで、縦動画（高さ > 幅）のみ `幅 × 9 / 16` を使う。正方形は横動画と同じ扱い。

- ASS の `Fontsize` は CSS の `font-size` より文字が小さく描かれる（漢字の幅で約 0.74〜0.78 倍。Windows で実測し、選ばれるフォントで変わる）。基準比率はこの差を含めた値で、実動画と Web の見比べで確定した（#372。ニコニコはその後、#387 でフォントの寸法からの換算に置き換えた）。文字の種類でフォントが異なるため、すべての文字で Web と同じ幅にはならない。
- ニコニコの Web 側の値は、再現 OSS [niconicomments](https://github.com/xpadev-net/niconicomments) の中サイズ 27 と描画範囲の高さ 384（高さの約 7%）に基づく（公式の仕様値ではない）。
- ビリビリの Web 側の値（高さの約 3.5%）は、未ログイン・360p 再生・devicePixelRatio 1.5 の Web プレイヤーで測った値で、本当の全画面と他の表示倍率は未測定。Web のサイズは動画枠に比例しないため、一般的な視聴サイズに多い値を固定の比率として使う。

変換後の出力は `{動画ファイル名}.{lang}.ass`（ニコニコは `.comments.ass`・ビリビリは `.danmaku.ass`）で、元のサイドカー（`*.comments.json` / `*.danmaku.xml`）と動画ファイルに並んで保存される。MKV 統合 ON 時は加えて `{動画ファイル名}.with-comments.mkv`、ハードサブ焼きこみ ON 時は加えて `{動画ファイル名}.hardsub.mp4` が生成される（いずれも元動画は触らず別ファイル・形式に依らず同一の出力名）。バイナリ `bin/danmaku2ass[.exe]` / `bin/ffmpeg/ffmpeg[.exe]` が欠如している場合や ffmpeg が失敗した場合は警告ログを出すのみで他機能には影響しない（ニコニコの ASS 変換は `danmaku2ass` が無くても動く）。

### ニコニコのコメントの変換

ニコニコのコメントはアプリ内の変換（[nico_ass.md](../../arch/nico_ass.md)）で ASS にし、Web 表示（再現 OSS niconicomments）に近づける。ビリビリの弾幕は従来どおり `danmaku2ass` で変換する。

- **対応するコマンド:** 位置（`ue` / `shita` / `naka`）、大きさ（`big` / `medium` / `small`）、色名、`#RRGGBB`、`invisible`、`_live`、フォント（`defont` / `gothic` / `mincho`）、`@秒数`。`#RRGGBB` は Web と同じく、プレミアム会員のコメントだけに効く（それ以外は白）
- **文字の大きさ:** Web と同じ大きさで描く。ASS の文字サイズはフォントの寸法から換算する（フォントが見つからないときは上記の基準比率 0.09）。「文字サイズ倍率」と「不透明度」は効く
- **表示時間:** 流れる速さと表示時間は Web と同じ計算で、「表示時間」の設定は使わない（`danmaku2ass` に切り替えたときだけ、その設定値が使われる）
- **文字の太さとフォント:** 変換した PC の OS のフォント名と太さを ASS に書く。Windows の既定フォントは Web と同じく、英字を Arial、それ以外を MS Pゴシックで描く。MS Pゴシックは Web（Windows の Chrome）と同じく擬似ボールドで太くなるので、文字の間隔も Chrome と同じだけ広げる（広げる量は、Chromium 156 / Windows 11 / devicePixelRatio 1.5 の Chrome で測った規則による。[#391](https://github.com/f8924919/yt-gui/issues/391)）。MKV を別の OS で再生すると、そのフォントが無い場合は代わりのフォントになる
- **配置:** 同時に表示されるコメントが重ならないように縦位置を決める。行が足りないときは画面内のランダムな位置に重ねる
- **4:3 の動画:** Web の 16:9 の舞台を動画の中央に置くので、動画の幅を超える部分のコメントは映らない。16:9 より横長の動画では、流れるコメントは動画の端から入って端へ出る
- **不正なコメント:** 1 件ずつ飛ばし、件数を警告ログに出す。ファイル全体が読めないときなどは `danmaku2ass` で変換する

次のものは再現しない。

- 複数行のコメントの縮小、`full` / `ender`、コメントアート、2017-07-12 より前のコメントの古い描画方式（[#388](https://github.com/f8924919/yt-gui/issues/388)）
- 投稿者コメントとニコスクリプト（取得データにスレッドの区別が無いため）
- 文字の幅はフォントで変わるので、Web と完全には一致しない
- Windows の既定フォントの小さい文字（文字の大きさが 22px 以下。small と、縮小されたコメント）では、Chrome が文字の幅を 1 字ずつ整数に丸めるので、幅がずれることがある（ふつうの文で 0.1% 程度、半角カナや句読点だけの文字列では数 %）
- 行が足りずにランダムな位置に置くコメントは、Web とは位置が違う（Web は毎回違う乱数で置く）。それに押されて、ほかの流れるコメントの段も Web と違うことがある

## 出力形式ラジオボタン

| 選択肢 | 動作 |
|---|---|
| *コンテナ* に結合（デフォルト） | `merge_output_format` を設定値のコンテナで指定。サムネイル埋め込みが可能 |
| remux のみ | コンテナ再結合のみ行い、再エンコードしない。サムネイル埋め込みチェックが無効化 |
| H.264 MP4 に再変換（互換性優先） | 映像を **H.264 / 音声を AAC に再エンコード**し、必ず再生互換性の高い MP4 を生成する。配信元が VP9 / AV1（webm / mkv）でも確実に MP4 になる。処理時間が増え画質が劣化する旨をツールチップで明示する。サムネイル・メタデータ・チャプター・字幕の埋め込みは「結合」と同様に可能 |
| 音声のみ (*ラベル*) | 音声トラックのみダウンロードし、`fmt_mp3` と同じ後段処理（FFmpegExtractAudio）で MP3 / FLAC に変換する。`*ラベル*` は設定の音声形式に応じて `MP3 192kbps` / `FLAC` |

コンテナ名は設定の動画コンテナに応じて変わります（例: `MP4 に結合` / `MKV に結合`）。「H.264 MP4 に再変換」を選んだ場合は設定のコンテナに関わらず出力は常に MP4 です。

### 「音声のみ」選択時の挙動

- 映像コンボを無効化（選択値は保持されるがフォーマット文字列生成時には無視）。
- 字幕リスト・字幕フォーマットコンボ・字幕埋め込みチェックを無効化し、選択をクリアする。
- 音声コンボはそのまま操作可能。音声を「ダウンロードしない」にした状態でキューに追加しようとすると専用警告 (`warn_skip_audio_only`) で弾く。
- サムネイル埋め込みは MP4 結合時と同様に有効。設定の音声形式が FLAC のときは埋め込まれない（既存 `fmt_mp3` と同じ挙動）。
- メタデータ・チャプター埋め込みは有効のまま。

## フォーマット文字列生成ロジック

映像・音声の選択状態に基づき、yt-dlp に渡す `format` 文字列を生成します。音声は multi-select のため、選択数で分岐します。

| 映像 | 音声選択数 | 生成される文字列 |
|---|---|---|
| 自動 | 0 (自動) | `bestvideo+bestaudio/best` |
| 自動 | 1 | `bestvideo+{aid}` |
| 自動 | 2 以上 | `bestvideo+{aid1}+{aid2}+...` |
| 特定 ID | 0 (自動) | `{vid}+bestaudio` |
| 特定 ID | 1 | `{vid}+{aid}` |
| 特定 ID | 2 以上 | `{vid}+{aid1}+{aid2}+...` |
| 複合 (★) | — | `{vid}` のみ |
| ダウンロードしない | 1 以上 | 音声 ID を `+` で連結 (`{aid}` または `{aid1}+{aid2}+...`) |
| 特定 ID | ダウンロードしない | `{vid}` のみ |

映像・音声の**両方**を「ダウンロードしない」に設定することはできません（警告を表示）。

### 「音声のみ」モードのフォーマット文字列

映像コンボは無視され、音声リストの選択値のみが使われます。**複数音声を選んでも先頭の 1 件のみが使用**されます（フェーズ 1）。

| 音声 | 生成される文字列 |
|---|---|
| 自動 | `bestaudio/best` |
| 特定 ID (単独 / 複数) | `{audio_id}` (複数選択時は先頭) |
| ダウンロードしない | 警告 (`warn_skip_audio_only`) で弾かれ、キュー追加不可 |

## リセット（`reset()`）

パネルを初期状態に戻すメソッドです。

リセット内容:

- 映像 / 音声 / 字幕の取得結果と選択をクリアし、コンボを「自動」1 項目のみに戻して無効化
- 出力形式ラジオを「MP4 に結合」に戻す
- 埋め込みチェックをデフォルト値（サムネイル: OFF、メタデータ / チャプター: ON）に戻す
- `_fetched_title` と `_pending_restore` も破棄

> パネルは [オリジナル形式ダイアログ](original-format-dialog.md) に内包され、ダイアログは追加成功・編集終了で破棄される（使い捨て）ため、運用上は破棄で状態が消えます。`reset()` 自体は単体テストやダイアログ内での再初期化に利用できる API として維持します。

---

## 編集モードでの設定復元

キューアイテムを右クリック→「形式を変更」で編集モードに入ると、前回の設定が自動的に復元されます。

- チェックボックス・ラジオボタン: **即時復元**（フォーマット取得前でも復元）
- 映像・音声・字幕の選択: **フォーマット取得後に復元**（取得が完了するまで `_pending_restore` に保持）

詳細は [ダウンロードキュー — 編集モード](../features/queue.md#編集モード) を参照。

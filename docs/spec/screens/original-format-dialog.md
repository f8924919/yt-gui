# オリジナル形式ダイアログ

[← 目次](../index.md)

> 関連実装: [yt_gui/original_format_dialog.py](../../arch/original_format_dialog.md)
> 内包パネルの詳細: [オリジナル形式パネル](original-format-panel.md)

## 概要

`OriginalFormatDialog(QDialog)` が実装するモーダルダイアログです。メインウィンドウの形式コンボで「オリジナルの形式」を選択したときに表示される **「詳細設定...」ボタン**から開きます。

従来メインウィンドウ上段にインライン埋め込みされていた [オリジナル形式パネル](original-format-panel.md)（`OriginalFormatPanel`）を、このダイアログ内に再ペアレントして表示します。映像・音声・字幕トラックの選択、出力形式、メタデータ・ニコニコ動画コメント設定はすべてパネル側の仕様に従います。本ドキュメントは **ダイアログとしての画面挙動（起動・ボタン・追加/編集フロー・破棄）** を規定します。

---

## ライフサイクル（使い捨て）

ダイアログは**開くたびに新規生成し、閉じたら破棄**します。永続インスタンスは持ちません。

- 生成時点の言語・動画コンテナ設定・音声ラベルで組み立てるため、表示中に言語設定が変わってもダイアログを再翻訳する必要はありません（次に開いたときに新しい言語で表示されます）。
- メインウィンドウは生存するダイアログ参照を保持せず、「開くファクトリ」とシグナルの受け口だけを持ちます。

---

## レイアウト構成

```
┌── オリジナルの形式の詳細設定 ───────────────────────┐
│ 動画URL: https://...                （読み取り専用）│
│                                                     │
│ [オリジナル形式パネル（OriginalFormatPanel）]       │
│   映像 / 音声 / 字幕 / 出力形式 / 埋め込み /         │
│   ニコニコ動画コメント …                            │
│                                                     │
├─────────────────────────────────────────────────────┤
│                          [キャンセル] [キューに追加] │
└─────────────────────────────────────────────────────┘
```

- 上部に対象 URL を読み取り専用で表示し、どの動画に対する設定かを明示します。
- 下部のボタン行は `QDialogButtonBox` 相当。主ボタンのラベルはモードで変わります（下表）。
- インライン埋め込み時の縦圧迫制約（音声/字幕の 2 カラム化・埋め込み 3 つを 1 行）はダイアログでは必須ではありませんが、本 PR ではパネルを再ペアレントするのみで内部レイアウトは現状を踏襲します（レイアウト緩和は別タスク）。

---

## モードとボタン

| モード | 主ボタン | 動作 |
|---|---|---|
| 追加 | キューに追加 | 検証 → `add_requested` を emit → `accept()` |
| 編集 | 変更 | 検証 → `edit_applied` を emit → `accept()` |

- 副ボタンは常に「キャンセル」。`reject()` し、編集モードでは `edit_cancelled` を emit します。
- ウィンドウの×（クローズ）も「キャンセル」と同じ扱い。

---

## 起動フロー（追加）

1. メインウィンドウの形式コンボで「オリジナルの形式」を選択（→ メイン側に「詳細設定...」ボタンが出る。詳細は [メインウィンドウ](main-window.md)）。
2. URL 入力欄に URL を入力。
3. 「詳細設定...」をクリック。**URL が空ならメインウィンドウ側で警告を出してダイアログは開かない**。
4. ダイアログが開く。必要に応じてパネルの「形式を取得」でトラック一覧を取得し、選択する。
5. 「キューに追加」をクリック。

### 「キューに追加」クリック時の検証（accept 前）

| 条件 | 表示 |
|---|---|
| 音声のみモードで音声が「ダウンロードしない」 | `warn_skip_audio_only`（ダイアログは開いたまま） |
| 結合モードで映像・音声とも「ダウンロードしない」 | `warn_skip_both`（ダイアログは開いたまま） |

検証を通過すると `add_requested` を emit して `accept()` します。実際のキュー追加（`build_job_spec` → enqueue）は [メインウィンドウ](main-window.md) / `App` 側で行います。

### 「未取得のまま追加」の扱い

形式を取得せずに「キューに追加」した場合も追加を許容します。`App` 側が `has_formats_loaded()` を見て分岐します。

- 取得済み → 選択値で即 enqueue（単独動画）。
- 未取得 → バックグラウンドでタイトル取得してから enqueue（単独動画）。

これにより、個別トラックを選ばず **auto 選択のまま出力モード・埋め込みオプション等だけ指定して単独動画を追加**するユースケースが維持されます。

> オリジナル形式はプレイリスト URL を**サポートしません**。未取得追加でプレイリスト URL を渡した場合、バックグラウンド取得でプレイリストと判明した時点で `warn_playlist_original_fmt` を表示して中止します（現行挙動踏襲）。

### ブラウザ拡張からの起動

ブラウザ拡張で `オリジナル形式`（アプリで選択）を選んで送ると、このダイアログが**追加モード**で自動起動します（仕様: [ブラウザ拡張連携 — オリジナル形式（アプリ側ダイアログ起動）](../features/browser-extension.md#オリジナル形式アプリ側ダイアログ起動)）。GUI からの起動との違いは次のとおりで、ダイアログ内の操作・検証・追加フローは同一です。

- 対象 URL は拡張から受信したものが使われ、メイン画面の URL 入力欄は介しません。
- 受信を機にメインウィンドウが前面化（最小化中は復元）します。
- トラックプローブ・確定後のダウンロードに、拡張由来のアイテム単位 Cookies が適用されます。
- 複数 URL を連続送信した場合は 1 件ずつ順にダイアログが開きます（多重起動しません）。
- **キャンセル時はキューに追加しません**（拡張の「アプリで詰める」意図のため）。

## 起動フロー（編集）

キューアイテムを右クリック →「形式を変更」で編集モードに入った単独のオリジナル形式アイテムについては、ダイアログが**編集モードで開き**、前回設定を復元します。

1. `App` が編集モードのダイアログを生成し、対象アイテムの `orig_settings` を渡す。
2. ダイアログはパネルに `restore_from_settings()` を適用（チェック・ラジオは即時、トラック選択は取得後に遅延適用）。
3. 続けて `trigger_fetch()` でフォーマットを取得し、取得完了後にトラック選択を復元する。
4. ユーザーが調整して「変更」をクリック → 検証（追加時と同じ）→ `edit_applied` を emit → `accept()`。
5. 「キャンセル」/ × → `edit_cancelled` を emit して閉じる。

編集対象の形式タイプ切替（オリジナル ↔ 他形式）はメインウィンドウの形式コンボで行います。詳細は [メインウィンドウ — 編集モード](main-window.md) と [ダウンロードキュー — 編集モード](../features/queue.md#編集モード) を参照。

---

## リセットについて

ダイアログは使い捨てのため、従来パネルが担っていた「追加成功 / 編集終了後のリセット」は不要です（破棄により状態が消える）。次回開いたときは新規パネルが初期状態で生成されます。

---

## 通知（ステータスバー）

複数音声 → MKV 自動昇格、音声のみモードでの複数音声トランケートのステータス通知は、ダイアログからのシグナルを受けて `App` 側で従来どおり発火します（[ダウンロード形式](../features/download-formats.md) / [オリジナル形式パネル](original-format-panel.md) 参照）。

# ダウンロード動作

[← 目次](../index.md)

> 関連実装: [yt_gui/downloader.py](../../arch/downloader.md)

## 概要

`Downloader` クラスが yt-dlp のラッパーとしてダウンロードを実行します。このドキュメントはダウンロードに関する動作仕様（ファイル名・プレイリスト・サムネイル埋め込み・字幕・Cookies）を記載します。

---

## ファイル名

### 基本テンプレート

yt-dlp の `outtmpl` に `%(title)s.%(ext)s` を指定します。拡張子は形式に応じて決まります。

| 形式 | 拡張子 |
|---|---|
| 最高画質 / 解像度指定 | 設定コンテナ（`.mp4` / `.mkv` / `.webm`） |
| MP3 | `.mp3` |
| FLAC | `.flac` |
| オリジナル形式（コンテナ結合） | 設定コンテナ |
| オリジナル形式（remux のみ） | 元のコンテナ |
| オリジナル形式（音声のみ） | `.mp3` または `.flac`（アプリ設定の音声形式に従う） |

### 重複回避

ダウンロード先に同名ファイルが既に存在する場合、上書きせず連番サフィックスを付与します。

```
タイトル.mp4        ← 既存
タイトル (1).mp4    ← 新規（自動リネーム）
タイトル (2).mp4    ← さらに既存なら
```

実装では、ダウンロード実行前に最終ファイルパスを計算して存在チェックを行い、`(n)` サフィックスを決定してから `outtmpl` を上書きします。

## プレイリスト

- プレイリスト URL を追加すると全エントリをキューに展開します
- ダウンロード先には **プレイリスト名のサブフォルダ** が自動作成されます
  - 例: `~/Downloads/プレイリスト名/動画タイトル.mp4`
- フォルダ名は以下のルールでサニタイズされます
  - `\ / : * ? " < > |` を `_` に置換
  - 100 文字で截断
  - 空になった場合は `"playlist"` を使用
- `yt_dlp` の `noplaylist: True` オプションを使用し、各エントリを個別ダウンロード

## サムネイル

### キュー表示用サムネイル（ツールチップ）

- キューアイテム追加時に `thumbnail_url` をバックグラウンドスレッドで取得
- `urllib.request` で取得し、base64 data URI にエンコードして `_thumbnail_cache` にキャッシュ
- ツールチップに 240×135px の `<img>` タグとして表示
- 取得失敗時は静かに無視（エラーを表示しない）

### ファイルへのサムネイル埋め込み

ダウンロードしたファイルにサムネイルを埋め込む機能です。

| 形式 | 埋め込み方法 | デフォルト |
|---|---|---|
| 最高画質 / 解像度指定 | `EmbedThumbnail` ポストプロセッサ（`writethumbnail: True` と組み合わせ） | ON |
| MP3 | `EmbedThumbnail` ポストプロセッサ（ID3 APIC タグ）| ユーザー選択（チェックボックス） |
| FLAC | サムネイル埋め込み不可 | — |
| オリジナル形式 | `EmbedThumbnail`（remux 時は無効）| ユーザー選択（チェックボックス） |

埋め込みに非対応のコンテナ（WebM）は自動スキップします。`_THUMBNAIL_EMBED_CONTAINERS` で対応コンテナを定義（`mp3`, `mkv`, `mka`, `ogg`, `opus`, `flac`, `m4a`, `mp4`, `m4v`, `mov`）。

## 字幕

オリジナル形式パネルで字幕を選択した場合に適用されます。

| 設定 | yt-dlp オプション |
|---|---|
| 手動字幕の選択 | `writesubtitles: True` |
| 自動生成字幕の選択 | `writeautomaticsub: True` |
| 言語コード | `subtitleslangs: [lang1, lang2, ...]` |
| フォーマット | `subtitlesformat: srt / vtt / best` |
| MP4 埋め込み | `FFmpegSubtitlesConvertor`（埋め込み前変換） + `FFmpegEmbedSubtitle` ポストプロセッサ |

字幕ファイルを個別に保存する場合（埋め込みなし）は、動画ファイルと同じフォルダに `.srt` / `.vtt` ファイルとして保存されます。

### JSON 字幕の自動変換

YouTube Live など `json3` 形式しか配信されない動画では、`FFmpegEmbedSubtitle` 単体だと `JSON subtitles cannot be embedded` のエラーで埋め込みに失敗します。これを避けるため、埋め込み有効時は `FFmpegSubtitlesConvertor` を埋め込み前に挟み、ユーザーが選んだフォーマット（`srt` / `vtt`）または `srt`（`best` 選択時のフォールバック）へ変換してから埋め込みます。

### サイドカー専用字幕の扱い（`live_chat` / `comments` / `danmaku`）

一部の抽出器は標準的な字幕フォーマットではないコメント・弾幕ログを字幕トラックとして公開します。これらは `FFmpegSubtitlesConvertor` / `FFmpegEmbedSubtitle` で変換も埋め込みもできないため、字幕リストには表示しつつ、埋め込みパスからは除外してサイドカーファイルだけが残るようにしています。

| lang | 由来 | 形式 | ラベル |
|---|---|---|---|
| `live_chat` | YouTube Live のチャットログ（`info["subtitles"]` / `info["automatic_captions"]` 双方に出現） | json | `live_chat – ライブチャット (埋め込み不可・サイドカー保存) [json]` |
| `comments` | ニコニコ動画コメント（`NiconicoIE._get_subtitles` が v1/threads JSON として出力） | json | `comments – ニコニコ動画コメント (埋め込み不可・サイドカー保存) [json]` |
| `danmaku` | ビリビリ動画の弾幕（`BiliBiliIE._get_subtitles` が `comment.bilibili.com/{cid}.xml` から取得する Bilibili XML） | xml | `danmaku – ビリビリ弾幕 (埋め込み不可・サイドカー保存) [xml]` |

`comments` / `danmaku` は[コメント・弾幕グループ](../screens/original-format-panel.md#コメント弾幕グループ)で ASS 変換・動画統合の対象になります（`live_chat` はサイドカー保存のみ）。

実装:

- 自動字幕ループでは `_SIDECAR_ONLY_SUB_LANGS = {"live_chat", "comments", "danmaku"}` をスキップ（手動扱いの 1 エントリだけが UI に出る）
- 「MP4 に埋め込む」が ON でかつ `subtitleslangs` にいずれかのサイドカー専用 lang が含まれるとき、`_StripSidecarOnlySubsBeforeEmbedPP` を `FFmpegSubtitlesConvertor` の前に差し込み、`requested_subtitles` から該当 lang を取り除く（ファイルはダウンロード済みなのでディスクには残る）
- 埋め込み OFF のときは convert/embed PP 自体が走らないため、フィルタも不要

## メタデータ・チャプター

ダウンロード後、`FFmpegMetadata` ポストプロセッサで動画ファイルにメタデータ・チャプターを埋め込めます。

- **最高画質 / 解像度指定**: 常に ON
- **オリジナル形式**: パネルのチェックボックスで制御（デフォルト ON）

## SponsorBlock

設定の SponsorBlock タブ（[設定ダイアログ](../screens/settings-dialog.md#sponsorblock-タブ)）で、コミュニティ提供の SponsorBlock データベースを参照してスポンサー区間等を処理します。設定は全ダウンロード共通で、設定保存後の次のダウンロードから（既存キューアイテムも含めて）反映されます。

- **処理方法**: `mark`（チャプター印付け）/ `remove`（区間除去）/ 無効（既定）。
- **対象カテゴリ**: `sponsor` / `selfpromo` / `interaction` / `intro` / `outro` / `filler` / `music_offtopic` から選択。
- 無効、またはカテゴリ 0 件のときは yt-dlp に SponsorBlock 関連オプションを渡しません。
- `mark` のときは印を出力に反映するためチャプター埋め込みを自動的に有効化します。
- 区間検出は `SponsorBlock` ポストプロセッサ、チャプター化・除去は `ModifyChapters` ポストプロセッサで行います（処理順の詳細は [downloader 実装](../../arch/downloader.md#sponsorblock)）。

## 区間ダウンロード

動画の**指定した一部分だけ**を出力として得る機能です。長尺動画から必要な部分だけを切り出したいときに使います。**既定は無効**です。指定方法は 2 モードあり、**排他**（どちらか一方のみ）です。

- **時間範囲**: 開始・終了時刻で 1 区間を指定する（#81）。
- **チャプター名**: チャプタータイトルにマッチする正規表現で指定する（#83）。マッチした各チャプターの区間を切り出す。

> **方式と通信量**: 動画を**いったん全体までダウンロードしてから、ローカルで指定区間を切り出します**（通信量の節約にはなりません）。yt-dlp のネイティブ区間ダウンロードは YouTube の DASH 形式で ffmpeg にネットワーク取得を委ねる経路となり、バンドル ffmpeg では不安定（環境によりクラッシュ / ハング）なため、安定性を優先してフル取得後にローカル ffmpeg で切り出す方式を採用しています（実装詳細は [downloader — 区間ダウンロード](../../arch/downloader.md#区間ダウンロード)）。

### 指定方法（時間範囲モード）

- メインウィンドウの区間指定 UI（[メインウィンドウ — 区間指定フィールド](../screens/main-window.md#区間指定フィールドダウンロード範囲)）で、有効化チェックをオンにし、モードで「時間範囲」を選んで**開始・終了**を入力します。
- 時刻は `HH:MM:SS` / `MM:SS` / 秒数（`90`）のいずれの表記でも受け付けます。
- 検証: 開始・終了がいずれも解釈可能で、かつ **開始 < 終了**。空欄不可。不正な場合は追加 / 変更をブロックして警告します。

### 指定方法（チャプター名モード）

- 区間指定 UI でモードに「チャプター名」を選び、チャプタータイトルにマッチさせる**正規表現**を入力します。
- マッチ判定は yt-dlp CLI の `--download-sections "chapter:<regex>"` と同じ **`re.search` セマンティクス**（部分一致・大文字小文字は区別）です。完全一致させたい場合は `^Chapter 1$` のようにアンカーを付けます。
- 検証: 正規表現としてコンパイル可能であること（`re.compile`）。空欄不可。不正な場合は追加 / 変更をブロックして警告します。
- **複数マッチ**: マッチしたチャプターごとに**個別ファイルへ分割出力**します（ファイル名は `動画タイトル - チャプター名.拡張子`）。少なくとも 1 件の切り出しに成功したら、フル動画の原本は削除します。各クリップには元動画のチャプター目次メタデータは複製しません（分割時に除去）。
- **マッチ 0 件・チャプター情報なし**: 切り出しは行わず、**フル動画をそのまま残して**警告ログを出します（エラーにはしません）。
- **ニコニコ動画のコメント後処理（ASS 変換・埋め込み・焼き込み）とは併用できません**。チャプター名モード指定時、コメント後処理は警告ログを出してスキップします。

### 適用範囲

- **全形式に適用**: 最高画質 / 解像度指定 / MP3・FLAC / オリジナル形式のいずれでも有効です（形式非依存）。
- **キューアイテム単位**: 区間はアイテムごとに保持されます（全 DL 共通設定ではありません）。設定値ではなくアイテムの実行設定（`JobSpec`）として持ちます。

### プレイリストの扱い

1 つの区間指定（時間範囲・チャプター名のいずれのモードも）を異なる複数動画へ一律適用する用途は想定しないため、**プレイリストには適用できません**。URL 入力時点では単一動画かプレイリストかを判定できないため、タイトル取得後にプレイリストと判明し、かつ区間が指定されている場合は警告を表示して追加を中断します（[メインウィンドウ — 区間指定フィールド](../screens/main-window.md#区間指定フィールドダウンロード範囲)）。同様に、複数アイテムをまとめて編集している間は区間 UI を無効化します。

### 正確なカット（再エンコード）

切り出し時の ffmpeg の動作を切り替えます（時間範囲・チャプター名の両モード共通）。

- 既定（OFF）: **キーフレーム境界**でカットします（stream copy）。再エンコードしないため高速・無劣化ですが、開始位置は指定時刻ぴったりにはならず最寄りのキーフレームにずれます。
- ON: カット境界を**再エンコード**し、指定時刻に正確に合わせます。処理時間が増えます。

実装の詳細は [downloader 実装 — 区間ダウンロード](../../arch/downloader.md#区間ダウンロード) を参照。

## ダウンロードアーカイブ

既にダウンロードした動画を記録し、再ダウンロードをスキップする機能です（yt-dlp の `--download-archive` 相当）。プレイリストを後日再追加したときの**差分取得**、および同一動画の**再 DL 防止**に使います。設定の「ダウンロード」タブ（[設定ダイアログ](../screens/settings-dialog.md#ダウンロードタブ)）で有効化します。**既定は無効**です。

### 記録の単位・タイミング

- 記録は **動画 ID 単位・フォーマット非依存**。yt-dlp が `{抽出器名小文字} {動画ID}` の 1 行を記録ファイルに追記します。
- 記録は **ダウンロードが完全成功したときのみ**。中断（一時停止）・エラーは記録しません。
- フォーマット非依存のため、720p で取得済みの動画を 1080p で取り直そうとしてもスキップされます。再取得したい場合はアーカイブをクリアしてください（アイテム単位での再取得は将来対応予定: #76）。

### 記録ファイルの場所

- **グローバル単一ファイル**。既定パスは設定ディレクトリ直下の `download_archive.txt`（[設定管理 — 保存先パス](../settings.md#保存先パス)と同じディレクトリ）。設定で任意のパスに変更できます。
- グローバルかつ ID 単位のため、**ダウンロードしたファイルを削除・移動しても記録は残り**、再 DL されません。全部取り直したい場合は設定画面の「クリア」で記録を消去します。

### キューでの効き方（プレフィルタ + DL 時スキップ）

| 効くタイミング | 動作 |
|---|---|
| **プレイリスト展開時（プレフィルタ）** | 追加時にアーカイブ済みエントリをキューに追加しません。全件がアーカイブ済みの場合はその旨を通知します。差分だけがキューに入ります。 |
| **ダウンロード実行時** | 対象がアーカイブ済みのときキューアイテムを **`skipped`（スキップ（アーカイブ済み））** にします（[キュー](queue.md#ステータス)参照）。単独 URL を明示追加した場合もここで拾います。 |

- プレフィルタは flat 抽出エントリの `id` / `ie_key` を yt-dlp の `in_download_archive` で照合するベストエフォート。最終的な記録済み判定は DL 実行直前のメタデータ抽出で再判定します（記録済みのとき yt-dlp の `extract_info` が結果を返さないことを利用。実装詳細は [downloader — ダウンロードアーカイブ](../../arch/downloader.md#ダウンロードアーカイブ)）。
- `download_archive` オプションは記録のために常に渡します（記録は本オプション経由でのみ行われるため）。yt-dlp は記録済み動画を黙ってスキップ（`finished` フック非発火）するため、アプリ側で実 DL 前に明示判定して `skipped` に遷移させます。

### アイテム単位でアーカイブを無視して再取得

アーカイブは ID 単位・フォーマット非依存のため、720p で取得済みの動画を 1080p で取り直す等ができません。これを救済するため、**待機中のキューアイテム単位で「今回だけアーカイブを無視して取得する」**操作を提供します。

- **操作**: キューアイテムを右クリック →「アーカイブを無視して再取得」（[メインウィンドウ — 右クリックコンテキストメニュー](../screens/main-window.md#右クリックコンテキストメニュー)）。
- **活性条件**: ダウンロードアーカイブが有効で、選択に `waiting` アイテムが含まれ、編集モードでないとき。対象は `waiting` アイテムだけです。
- **効果**: 当該アイテムは archive 照合・スキップの対象外になり、記録済みでも再ダウンロードされます。
- **表示**: フラグが立ったアイテムはツールチップに「アーカイブ無視: 有効」が 1 行表示されます。ステータスは `waiting` のままです。

#### 再記録の扱い

**既存のアーカイブ記録は保持し、この再取得は記録しません**。

- 既に記録済みなら、その記録はそのまま残ります（消去しません）。
- 今回の再取得自体はアーカイブに記録されません。
- そのため**次回（フラグ無し）の通常ダウンロードでは既存記録により再びスキップ**されます。「アーカイブを無視して再取得」は**一回限りの上書き**です。

> yt-dlp は `download_archive` を渡すと記録済み動画を内部でスキップするため、再取得するには当該アイテムだけ `download_archive` を渡さない必要があります。その結果「スキップしない＝記録もしない」挙動になります（実装は [downloader — ダウンロードアーカイブ](../../arch/downloader.md#ダウンロードアーカイブ)）。

#### 既知の制限

フラグを立てた後に「形式を変更」で編集すると、`JobSpec` が再生成されフラグは解除されます（編集フォームに該当 UI が無いため）。編集後に再取得したい場合は、編集完了後にメニューを再実行してください。

### 重複回避との関係

[重複回避](#重複回避)（同名ファイルの `(n)` リネーム）とは目的が異なり**非競合**です。アーカイブは「同一動画の再 DL 自体を止める」、`(n)` リネームは「別動画の同名ファイル衝突を避ける」ものです。

## Cookies

認証が必要な動画（会員限定など）のダウンロードに使用します。

### ファイル指定

設定の `cookies_path` が有効なファイルパスを指す場合、`cookies` オプションとして yt-dlp に渡します。

### ブラウザから取得

設定の `cookies_browser` が設定されている場合、`cookiesfrombrowser` オプションとして yt-dlp に渡します。ブラウザ設定がファイル設定より優先されます。

### Cookies ファイルが見つからない場合

ダウンロード実行時にファイルが存在しない場合は警告ダイアログを表示し、Cookies なしでダウンロードを続行します。

### アイテム単位の Cookies（拡張連携）

ブラウザ拡張から送られたクッキーは、グローバル設定（`cookies_path` / `cookies_browser`）と独立して、そのキューアイテムにのみ適用されます（優先順位: アイテム固有 > グローバル設定）。手動追加アイテムは従来どおりグローバル設定を使用します。詳細は [ブラウザ拡張連携](browser-extension.md) を参照してください。

## 依存バイナリのパス解決

`Downloader.__init__()` で以下の方法でパスを決定します。

- **PyInstaller バイナリ時**: `sys._MEIPASS` 直下（バンドル時は `bin/` 階層がフラット化される）
- **開発時**: プロジェクトルートの `bin/` 以下

| バイナリ | パス |
|---|---|
| deno | `{base}/deno[.exe]` |
| ffmpeg | `{base}/ffmpeg/ffmpeg[.exe]` |
| ffprobe | `{base}/ffmpeg/ffprobe[.exe]` |

# ブラウザ拡張連携

[← 目次](../index.md)

> 関連実装: [extension_server.py](../../arch/extension_server.md)（受信サーバー）・[app.py — ブラウザ拡張連携](../../arch/app.md#ブラウザ拡張連携)（配線）・[queue_controller.py](../../arch/queue_controller.md)（アイテム単位 Cookies）・拡張機能本体は [`extension/`](../../../extension/README.md)。
> 関連仕様: [ダウンロードキュー](queue.md) ・ [ダウンロード動作 — Cookies](download-behavior.md#cookies) ・ [設定管理](../settings.md)

## 概要

ブラウザで開いている動画ページから、URL と認証クッキーをワンクリックで yt-gui のダウンロードキューへ送る機能です。ブラウザとアプリを往復して URL をコピーしたり、cookies.txt を手動エクスポートする手間をなくします。

クッキーは拡張機能の `chrome.cookies` API で取得して送るため、cookies.txt の手動エクスポートや `--cookies-from-browser`（App-Bound Encryption）の問題を回避できます。

構成要素は次の 3 つです。

1. **ローカル受信サーバー**（yt-gui 内、既定は無効）
2. **ブラウザ拡張機能**（Chromium 系。Chrome / Edge / Brave など）
3. **アイテム単位 Cookies**（拡張由来のクッキーをキューアイテムへ紐付け）

---

## 全体フロー

```
[拡張] 動画タブで「yt-gui に送る」
   │  ① 現在タブの URL を取得
   │  ② chrome.cookies で当該ドメインのクッキーを取得 → Netscape 形式へ整形
   │  ③ POST /enqueue {url, cookies, format}（127.0.0.1、トークン認証）
   ▼
[yt-gui ローカルサーバー]
   │  ④ トークン・Origin を検証
   │  ⑤ クッキーを一時 cookies.txt に保存（権限 0600）
   │  ⑥ 受信クッキー付きで fetch_title_or_entries → タイトル/エントリ取得
   │  ⑦ キューアイテムを生成（url + cookies_path をアイテムに保持）
   ▼
[キュー] 既存のダウンロード経路で実行（DL 時もアイテムのクッキーを使用）
```

## ローカル受信サーバー

| 項目 | 仕様 |
|---|---|
| 有効/無効 | 設定で切替。**既定は無効**（オプトイン。任意のローカルプロセスに口を開けないため） |
| バインド | `127.0.0.1` のみ（`0.0.0.0` 不可） |
| ポート | 既定 `8718`、競合時はフォールバック `8719` → `8720` を順に試す |
| 認証 | リクエストごとに共有トークン必須。欠如/不一致は `403` |
| Origin 制限 | `chrome-extension://` スキームの origin のみ受理。`http(s)://` の Web ページ origin は `403`（任意 Web ページからの CSRF 防止）。拡張個体の束縛はトークンが担う（unpacked では拡張 ID が固定しづらいため、特定 ID へのピン留めは将来拡張） |
| ログ | クッキー値・トークンは記録しない |

既定ポート `8718` は、主要ダウンローダ（aria2 `6800` / JDownloader `9666` / Zotero connector `23119`）や代表的な開発サーバと衝突しにくい値として選定しています。

### エンドポイント: `POST /enqueue`

リクエスト（JSON）:

| フィールド | 必須 | 説明 |
|---|---|---|
| `url` | ○ | ダウンロード対象 URL |
| `cookies` | － | Netscape 形式の cookies.txt 文字列。省略時はグローバル設定にフォールバック |
| `format` | － | 形式指定オブジェクト。省略・`app_default`・不正値はアプリ側の既定形式を使用する。`kind: "original"` はアプリ側でオリジナル形式ダイアログを開く（下記「形式指定オブジェクト」「オリジナル形式（アプリ側ダイアログ起動）」） |

レスポンス:

| 状況 | ステータス | ボディ |
|---|---|---|
| 受理（キュー追加を開始） | `200` | `{"ok": true}` |
| 認証失敗（トークン/Origin） | `403` | `{"ok": false, "error": "unauthorized"}` |
| URL 不正・JSON 不正・`format` 不正 | `400` | `{"ok": false, "error": "..."}`（`invalid_url` / `invalid_json` / `invalid_format` 等） |
| メソッド/パス不一致 | `404` / `405` | `{"ok": false, "error": "..."}` |

> **タイトル取得は非同期**: タイトル取得はネットワークを伴い時間がかかるため、サーバーはリクエストを受理した時点で即座に `200` を返し、実際のタイトル取得・キュー行の確定はアプリ側がバックグラウンドで行います（既存の[キュー追加フロー](queue.md#キューへの追加フロー)と同じ）。したがってレスポンスにタイトルは含めません。取得失敗時はアプリのログ・ステータスに表示します。

### 形式指定オブジェクト（`format`）

拡張のポップアップで選んだ形式を、yt-dlp フォーマット文字列ではなく**意味（kind＋パラメータ）**として送ります。形式定義の解決はアプリ側（[formats.py](../../arch/formats.md) / [job_spec.py](../../arch/job_spec.md)）に一任し、拡張は yt-dlp セレクタを組み立てません（形式定義の単一ソース維持）。

```json
{
  "kind": "best | resolution | audio | original | app_default",
  "resolution": "1080",        // kind=resolution のときのみ
  "audio_format": "mp3|flac",  // kind=audio のときのみ
  "mp3_bitrate": "192"         // kind=audio かつ mp3 のときのみ
}
```

| kind | 意味 | アプリ側の挙動 |
|---|---|---|
| `best` | 最高画質 | `fmt_best_mp4` |
| `resolution` | 解像度指定 | `fmt_720p`（`resolution` を適用） |
| `audio` | 音声のみ | `fmt_mp3`（`audio_format` / `mp3_bitrate` を適用） |
| `original` | オリジナル形式（トラック個別選択） | アプリ側で[オリジナル形式ダイアログを開く](#オリジナル形式アプリ側ダイアログ起動)（追加パラメータなし） |
| `app_default` | アプリ既定に委ねる | メイン画面で選択中の形式 |

**コンテナ（mp4/mkv/webm）は送りません。** コンテナはアプリのグローバル設定であり拡張からは知り得ないため、拡張のラベルにもコンテナ名を焼き込まず、実出力コンテナはアプリ設定（[ダウンロード形式](download-formats.md)）に従います。

**オリジナル形式（トラック個別選択）は `kind: "original"` で指定します。** ただしトラック個別選択は対話的なプローブが必要でポップアップに不向きなため、拡張は形式を確定せず「アプリで詰める」意図だけを送り、トラック選択はアプリ側のダイアログで行います（[オリジナル形式（アプリ側ダイアログ起動）](#オリジナル形式アプリ側ダイアログ起動)）。`kind: "original"` に追加パラメータはありません。

**入力は信頼しない（クランプ）。** アプリ側は受信した `resolution` / `audio_format` / `mp3_bitrate` を許可値（[`VIDEO_RESOLUTIONS` / `AUDIO_FORMATS` / `MP3_BITRATES`](download-formats.md#設定値の選択肢)）へクランプし、未知/欠落・未知の `kind`・`format` 全体の欠落はすべてアプリ既定形式へフォールバックします。任意の yt-dlp フォーマット文字列を注入する経路は設けません。

- `audio_format` / `mp3_bitrate` は**そのキューアイテムにのみ**適用されます（アイテム単位の上書き）。グローバル設定は変更しません。
- `format` が JSON オブジェクト（dict）以外（文字列・配列・数値等）の場合は `400`（`invalid_format`）。欠落は許容しアプリ既定で進めます。

> プロトコルは前方互換に保ち、未知の `kind` や余分なフィールドが来てもアプリ既定へフォールバックして受理します。

### オリジナル形式（アプリ側ダイアログ起動）

`kind: "original"` を受けたときは、形式を即確定せず**アプリ側で[オリジナル形式ダイアログ](../screens/original-format-dialog.md)を開いて**トラック（映像 / 音声 / 字幕）を対話選択します。拡張は「アプリで詰める」意図のみを送り、トラックプローブと選択はアプリが担います。

| 論点 | 仕様 |
|---|---|
| 起動 | 受信を機にメインウィンドウを前面化（最小化中なら復元）し、対象 URL のオリジナル形式ダイアログを開く |
| 非同期との整合 | `/enqueue` は従来どおり即 `200` を返す。ダイアログ起動はアプリ側がメインスレッドで行う |
| 複数 URL の連続送信 | `original` 意図は内部キューに積み、**1 件ずつ直列でダイアログを表示**する（多重モーダルの同時起動を防止） |
| Cookies | 拡張由来のアイテム単位 Cookies を、ダイアログでの**トラックプローブ**・**確定後のダウンロード**双方に適用する |
| 確定 | ダイアログで確定するとキューへ追加する（選択トラック＋アイテム単位 Cookies を保持） |
| キャンセル | **キューに追加しない**（「アプリで詰める」意図のため、キャンセル＝送信の取りやめ） |

> ダイアログはモーダルだが、`/enqueue` 応答（`200`）はダイアログ表示前に返るため、拡張側はアプリのダイアログ操作を待たない。

### ペアリング（トークン交換）

1. 設定画面の「ブラウザ連携」項目でサーバーを有効化するとトークンを表示する。
2. ユーザーが拡張のオプション画面にトークンを貼り付ける。
3. 以降、拡張は全リクエストにトークンを付与する。

## ブラウザ拡張機能

| 項目 | 仕様 |
|---|---|
| 対応ブラウザ | Chromium 系（Manifest V3）。コードは共通、配布は当面 unpacked（開発者モードで読み込み） |
| 起動操作 | ツールバーボタン → **ポップアップ**で形式を選んで送信／ページ右クリックメニュー「yt-gui に送る」は記憶済み形式でワンクリック送信 |
| 形式選択 | ポップアップで `最高画質` / `解像度指定`（解像度サブ選択）/ `音声のみ`（mp3・flac、mp3 はビットレート）/ `オリジナル形式`（アプリで選択）/ `アプリの既定を使う` を選ぶ（下記「ポップアップ（形式選択）」） |
| クッキー取得 | `chrome.cookies.getAll({ url })` で当該 URL に適用されるクッキーを取得 |
| 整形 | Netscape cookies.txt 形式へ変換して送信 |
| 権限 | `cookies`、`host_permissions` に `<all_urls>`（任意の動画サイトのクッキー読み取り用）と `http://127.0.0.1/*`（ローカル送信用） |
| 設定 | オプション画面でトークンとポートを設定 |
| 結果表示 | ツールバーアイコンのバッジ（`OK` / `403` / `OFF` / `KEY` / `ERR`）で送信結果を通知 |
| ポート追従 | 設定ポート → +1 → +2 を順に試し、接続失敗時のみ次へ（アプリのフォールバックに追従）。HTTP 応答が返ったら停止 |
| 多言語 | オプション画面の表示はブラウザの UI 言語に追従（日本語 / 英語）。未対応言語は英語へフォールバック |
| アイコン | アプリ本体と同一（`assets/icon.png` 由来）。ツールバー・拡張一覧に表示 |
| バージョン | `manifest.json` の `version` はアプリ本体（`pyproject.toml`）と同期 |

> Manifest V3 の Service Worker は常駐しないため、送信時に都度 `fetch` する設計とし、常時接続は張りません。

実体は [`extension/`](../../../extension/README.md) に配置。開発時は unpacked（開発者モード）で読み込み、リリース時は zip 成果物（後述）を配布します。

### ポップアップ（形式選択）

ツールバーボタンをクリックすると**ポップアップ**が開き、形式を選んで送信します。

- 構成: 主ボタン「yt-gui に送る」＋形式セレクタ。`解像度指定` のときは解像度（480/720/1080/1440/2160）、`音声のみ` のときは音声形式（mp3/flac）と mp3 ビットレート（128/192/256/320）のサブ選択を出し分ける。`オリジナル形式`（アプリで選択）はサブ選択を持たず、トラック選択はアプリ側ダイアログに委ねる（[オリジナル形式（アプリ側ダイアログ起動）](#オリジナル形式アプリ側ダイアログ起動)）。
- **既定動作**: 主ボタンは**前回選択した形式**で送信する。前回選択は `chrome.storage`（拡張側）に保持し、アプリ設定とは独立。初回の既定は `アプリの既定を使う`（= `format` に `kind: app_default` を送るか、`format` を省略）。
- 送信形式は[形式指定オブジェクト](#形式指定オブジェクトformat)として `POST /enqueue` の `format` に載せる。
- **ワンクリック送信**は右クリックメニュー「yt-gui に送る」で維持する（記憶済み形式で即送信、ポップアップを開かない）。
- 多言語: 形式ラベルもオプション画面と同じ国際化機構（`_locales` ja/en）で表示する。

> Manifest V3 では `action` に `default_popup` を設定するとツールバークリックでポップアップが開き、`chrome.action.onClicked` は発火しなくなる。そのため送信トリガはポップアップの送信ボタンへ移し、即送信は右クリックメニュー（`contextMenus`）が担う。

### 多言語（オプション画面）

- Chrome 標準の国際化機構（`_locales/<lang>/messages.json` + `chrome.i18n.getMessage()`）を用い、**ブラウザの UI 言語に自動追従**する。対応は日本語（`ja`）/ 英語（`en`）。
- `manifest.json` に `default_locale: "en"` を設定し、未対応言語は英語へフォールバックする。
- `manifest.json` の `name` / `description` は**英語固定**（ストア表記の一貫性のため `__MSG_*__` による多言語化は行わない）。多言語化の対象はオプション画面の文言に限る。

### アイコン

- アプリ本体と同一のアイコン（`assets/icon.png`）から生成した 16 / 32 / 48 / 128 px の PNG を `extension/icons/` に配置し、`manifest.json` の `icons` と `action.default_icon` に設定する。
- 生成は [`scripts/build_extension_icons.py`](../../../scripts/build_extension_icons.py)（Pillow）で行い、生成物はコミットする（unpacked 読み込み・zip 配布のいずれでも同梱が必要なため）。

### バージョン同期

- 拡張のバージョンはアプリ本体と一致させる。**単一ソースは `pyproject.toml` の `[project] version`**（[version-single-source](../../task/archive/version-single-source.md) と同方針）。
- [`scripts/sync_extension_version.py`](../../../scripts/sync_extension_version.py) が `pyproject.toml` の version を読み、`extension/manifest.json` の `version` を書き換える（冪等）。
- リリース時に CI（`release.yml`）が zip 化の前にこのスクリプトを実行し、配布物の version を一致させる。**実行時に動的同期はしない**（リリース時固定）。

### リリース zip

- リリース時、CI が拡張一式（`manifest.json` / `background.js` / `popup.*` / `format_choice.js` / `options.*` / `_locales/` / `icons/`）を `yt-gui-extension-{version}.zip` に固め、GitHub Release のアセットとして添付する。
- zip の version はバージョン同期後の値で、アプリ本体と一致する。詳細は [docs/build.md](../../build.md) を参照。

## アイテム単位 Cookies

- 拡張由来のクッキーは、グローバル設定（`cookies_path` / `cookies_browser`）とは独立に、**そのキューアイテムにのみ適用**されます。
- 適用範囲: 追加時のメタデータ取得・実ダウンロードの両方。
- 優先順位: **アイテム固有 > グローバル設定**。
- 手動追加アイテム（拡張を介さない）は従来どおりグローバル設定を使用します（既存挙動は非破壊）。
- アイテム単位で扱うのは **cookies ファイル（path）のみ**です。`cookiesfrombrowser` は「ローカルブラウザを yt-dlp が直接読む」概念で拡張連携と排他のため、アイテム単位には持たせません。

詳細は [ダウンロード動作 — Cookies](download-behavior.md#cookies) を参照してください。

---

## 一時 Cookies ファイルのライフサイクル

- 保存先: アプリ専用の一時ディレクトリ（`tempfile.TemporaryDirectory`）。各ファイルの権限はユーザーのみ（POSIX 0600）。
- 削除: **アプリ終了時に一時ディレクトリごと一括削除**する（MVP）。アイテム完了/削除時の即時削除は将来の最適化とする。
- 削除失敗は非致命（ログのみ）。

## プレイリスト URL の扱い

拡張から単一動画 URL を送った場合、そのアイテムに Cookies を紐付ける。拡張からプレイリスト URL を送った場合は、取得した全エントリに同一の Cookies を適用する（[キュー追加フロー](queue.md#キューへの追加フロー)に従い展開）。

---

## セキュリティ要件（最低ライン）

- `127.0.0.1` バインド限定・トークン必須・Origin 制限の 3 点は省略不可。
- クッキーは設定ファイル等へ永続化しない（一時ファイルのみ・短命）。
- ログにクッキー値・トークンを残さない。

# ビリビリの弾幕の取得元を変える案の見送り

> Issue: [#373](https://github.com/f8924919/yt-gui/issues/373)
> ステータス: 見送り（2026-11-03）
> ブランチ: `docs/373-bilibili-danmaku-decision`
> 基点: `c4f324e`

## 判断

ビリビリの弾幕は、これまでどおり yt-dlp が取得する XML を使う。Web プレイヤーが使う別の窓口へ切り替える実装は行わない。

**理由:** その窓口はビリビリの非公開 API である。非公開 API の文書をまとめていた `bilibili-API-collect` は、2026-01-28 にビリビリが委託した法律事務所から警告を受け、永久に停止した（同リポジトリの README で確認）。公開配布するアプリから非公開 API を直接呼ぶ実装は、弾幕の再現度という利点に対して見合わないと、ユーザーが判断した。法的な評価を行ったものではない。

## 分かったこと

- XML は弾幕の一部だけを返す。`BV1p5411a7nL`（35 秒、総数の表示 10,652 件）では 360 件のうち 320 件が同じ文言で、時間も前半に偏っていた。
- Web で見える巨大な斜めの文字は、動画本体ではなく位置指定の弾幕（mode 7）だった。この動画の XML には mode 7 が 1 件も入っていなかった。
- ビリビリの取得の不足は動画によって異なる。別の 2 本の動画では、XML のほうが件数が多かった。
- ASS 変換は原因ではない。XML の件数と ASS の Dialogue の件数は一致した。

## 見送りの影響

Web と同じ弾幕にならない動画が残る。ユーザー向けの制約は [ダウンロード動作](../../spec/features/download-behavior.md) に書いた。

## 再検討する条件

- yt-dlp が上流で同等の取得に対応したとき（yt-dlp の更新で取り込める）。
- ビリビリが公開 API を提供したとき。

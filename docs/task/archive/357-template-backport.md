## design-review を受けた設計の確定（2026-10-23・主エージェント判断）

- 「繰り返し使う検出器」は **性質で定義**（追跡下に残して繰り返し走らせる検出器。§2.6 の「全部」と一致させる）。harness.md の `paths` は目安（paths には `pyproject.toml` の lint 設定などが無く、paths を正本にすると A1 が §2.6 より狭くなる）。
- 一度で捨てるプローブ = 証跡の段で「よくない」側の書き先の主張を支える、追跡外のタスク限りの**スクリプトのファイル**。1 行のコマンドは対象外。証跡はプローブ本文と `git hash-object`（コミット hash は追跡外のファイルを固定しないため）。evaluator 進め方 2 の判定材料に「貼られたプローブ」を足す（diff に現れないため）。
- 段の表の A11 は §8.1 と揃えて欠番行を置く。shell の罠の行は置かず、理由を「雛形との違い」に書く。
- evaluator の指摘への対応で生じた書き換えは、docs-guide §3.2 のとおり訂正ログに載せない（git-workflow の子項目「訂正ログとの関係」に明記）。

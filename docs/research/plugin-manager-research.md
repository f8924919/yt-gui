# プラグイン管理機能 踏査メモ

## 1. yt-dlp プラグインシステムの仕様

### 1.1 ロード順序とスキャンパス

`YoutubeDL` 初期化時、yt-dlp は以下の順でプラグインを探索する。

| 優先度 | パス | 説明 |
|--------|------|------|
| 1 | `sys.path` 上の各エントリ配下の `yt_dlp_plugins/` | pip パッケージ形式 |
| 2 | ユーザー設定ディレクトリ配下の `plugins/` | ファイル配置形式 |

ユーザー設定ディレクトリの実パス：

| OS | パス |
|----|------|
| Windows | `%APPDATA%\yt-dlp\` |
| macOS | `~/Library/Application Support/yt-dlp/` |
| Linux | `$XDG_CONFIG_HOME/yt-dlp/`（未設定時は `~/.config/yt-dlp/`） |

### 1.2 プラグインの種類

| 種類 | 用途 | ディレクトリ |
|------|------|--------------|
| Extractor | 対応サイトの追加 | `plugins/extractor/` |
| Post-processor | ダウンロード後処理の追加 | `plugins/postprocessor/` |

yt-dlp の公式ドキュメントではサブディレクトリ分けが推奨されているが、`plugins/` 直下に置いても認識される（バージョン依存の可能性あり）。

### 1.3 サポートされるファイル形式

- **`.py` 単一ファイル** — 最もシンプル。1サイト対応などの軽量プラグインに多い。
- **`.zip` アーカイブ** — 複数ファイルで構成されるプラグイン。zip 内に `yt_dlp_plugins/` ディレクトリ構造を持つ。

### 1.4 pip パッケージ形式

`yt-dlp-<name>` という名前で PyPI に公開されるプラグインは、インストールすると `yt_dlp_plugins` 名前空間パッケージとして `site-packages/` に展開される。  
→ **PyInstaller バンドル環境では事実上使用不可**（後述）。

## 2. 現行アーキテクチャとの関係

### 2.1 YoutubeDL のインスタンス生成タイミング

`downloader.py` では `fetch_title_or_entries` / `fetch_formats` / `download_video` それぞれが `with YoutubeDL(opts) as ydl:` を都度生成する。  
→ ファイルをプラグインフォルダに配置すれば、**次回の操作から自動的に読み込まれる**可能性が高い（後述の制約あり）。

### 2.2 設定フォルダとの分離

このアプリの設定は `%APPDATA%/yt-gui/` に保存されているが、yt-dlp プラグインフォルダは `%APPDATA%/yt-dlp/plugins/` と別系統。  
→ プラグイン管理 UI からは yt-dlp の公式パスを直接操作する設計になる。

## 3. 想定 UI 設計

### 3.1 配置方針

`SettingsDialog` の `QTabWidget` に **「プラグイン」タブ** を追加する。既存の「一般」「画質・音質」タブと同じパターンで実装できる。

### 3.2 レイアウト案

```
┌─────────────────────────────────────────────────────────────┐
│ 一般 │ 画質・音質 │ プラグイン                               │
├─────────────────────────────────────────────────────────────┤
│ フォルダ: C:\Users\...\AppData\Roaming\yt-dlp\plugins  [開く] │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ bilibili_ie.zip            extractor   2024-03-10      │ │
│ │ mysite_pp.py               postprocessor  2024-01-05   │ │
│ │                                                        │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                     [追加...]   [削除]       │
│                                                              │
│ ⚠ プラグインは任意のPythonコードを実行します。               │
│   信頼できるソースのファイルのみ追加してください。           │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 各ウィジェットの役割

| ウィジェット | 型 | 動作 |
|--------------|----|------|
| フォルダパス表示 | `QLabel` | yt-dlp プラグインフォルダのフルパスを表示 |
| 「開く」ボタン | `QPushButton` | `QDesktopServices.openUrl()` でエクスプローラー/Finder を開く |
| プラグイン一覧 | `QListWidget` | `plugins/` 以下の `.py` / `.zip` をスキャンして表示 |
| 「追加」ボタン | `QPushButton` | `QFileDialog` で `.py` / `.zip` を選択 → フォルダへコピー |
| 「削除」ボタン | `QPushButton` | 選択中のファイルをフォルダから削除（確認ダイアログつき） |
| 警告ラベル | `QLabel` | セキュリティ注意文を常時表示 |

### 3.4 一覧に表示する情報

- ファイル名
- 推定タイプ（ファイル名や zip 内パスから `extractor` / `postprocessor` / `不明` を判定）
- 更新日時（`os.path.getmtime()`）

プラグインにバージョン・説明などの標準メタデータ仕様がないため、それ以上の情報表示は困難。

## 4. 実装上の課題

### 4.1 PyInstaller バンドル時のスキャンパス問題（要検証）

**リスク度: 高**

PyInstaller でビルドすると `sys.path` の内容が通常の Python 環境と異なる。yt-dlp が `sys.path` ベースでプラグインを探す処理（`yt_dlp.utils.plugins` 内）が、バンドル環境で正しく動作するかは**実機テストが必須**。

ユーザー設定ディレクトリ配下のスキャンは `sys.path` に依存しないため、こちらは動作する可能性が高い。それでも確認が必要。

**確認方法:** バンドル済みバイナリを使った状態でプラグインフォルダにテスト用プラグインを置き、yt-dlp がロードするかを検証する。

### 4.2 追加後の即時反映とモジュールキャッシュ問題

**リスク度: 中**

Python の `import` システムはモジュールを `sys.modules` にキャッシュする。yt-dlp のプラグインローダーがプロセス起動後に一度だけ実行される場合、`YoutubeDL` を都度生成してもプラグインが読み込まれない可能性がある。

調査が必要な点：
- yt-dlp のプラグインスキャンが `YoutubeDL.__init__` のたびに走るか、モジュール import 時に一度だけ走るか
- `yt_dlp.plugins` モジュールの `load_plugins()` の呼び出しタイミング

現実的な対処: 追加・削除後にダイアログ内で「変更はアプリ再起動後に反映されます」と表示する方針が安全。

### 4.3 プラグインメタデータの取得困難

**リスク度: 低（UX への影響のみ）**

yt-dlp プラグインに標準メタデータ仕様（バージョン、説明、作者）がないため、コード解析なしに詳細情報を表示できない。zip ファイル内の `README.md` や `__version__` を検索する実装は可能だが、プラグインごとに形式が異なるため網羅は困難。

→ 表示項目はファイル名と日時に留めるのが現実的。

### 4.4 pip パッケージ形式への非対応

**リスク度: 低（スコープ外）**

PyPI の `yt-dlp-<name>` パッケージは PyInstaller バンドルの隔離 Python 環境には install できないため、今回のスコープ外とする。「ファイル（.py / .zip）のみサポート」と明示すれば問題ない。

### 4.5 セキュリティ

プラグインはアプリと同じユーザー権限で任意の Python コードを実行できる。  
→ UI 内に常時警告文を表示する。削除確認ダイアログと同様に、追加時にも確認ダイアログを出すか検討。

### 4.6 ダイアログサイズの変更

現在 `SettingsDialog` は `setFixedSize(480, 355)` で固定サイズ。プラグインタブを追加するとリストを表示するスペースが足りないため、タブ切り替え時に高さを変更するか、全体のサイズを広げる必要がある。  
→ タブ切り替えシグナル (`currentChanged`) で `setFixedSize()` を動的に変更する方法が既存パターンと合致する。

## 5. 実装スコープ案

### フェーズ1（最小実装）

- yt-dlp プラグインフォルダの自動作成
- フォルダ内の `.py` / `.zip` 一覧表示
- ファイル追加（コピー）
- ファイル削除（確認ダイアログつき）
- 「フォルダを開く」ボタン
- セキュリティ警告文の常時表示
- 多言語対応（`ja.py` / `en.py` へのキー追加）

### フェーズ2（任意拡張）

- zip 内の構造解析による extractor / postprocessor 分類表示
- 追加時の確認ダイアログ（セキュリティ強化）
- プラグインの有効/無効切り替え（ファイル名に `.disabled` サフィックスを付与する方式）

### 対応しない機能

- pip パッケージの install / uninstall
- プラグインのネットワーク経由インストール（GitHub URL 指定など）
- プラグインのバージョン管理

## 7. 未検証事項（実装前に確認が必要）

1. PyInstaller バンドル版で `%APPDATA%/yt-dlp/plugins/` 配下のプラグインが実際にロードされるか
2. yt-dlp のプラグインスキャンが `YoutubeDL` 生成のたびに走るか（`yt_dlp/plugins.py` のソースを読む）
3. サブディレクトリなし（`plugins/` 直下）への `.py` 配置でプラグインが認識されるか
